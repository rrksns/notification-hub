# Alerting Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Prometheus 경보를 Alertmanager를 통해 Webhook과 SMTP 이메일로 동시에 전달한다.

**Architecture:** Prometheus는 규칙 파일을 평가하고, Alertmanager는 기본 route에서 Webhook과 이메일 receiver로 동시에 전달한다. Docker Compose 환경에서 설정 파일과 SMTP 비밀번호 Secret 파일을 마운트하고, 나머지 endpoint 값은 환경변수로 주입한다. 현재 확인된 메트릭만 규칙에 사용하며, 없는 DLQ와 Provider 메트릭은 계측 없이는 규칙을 추가하지 않는다.

**Tech Stack:** Prometheus, Alertmanager, Docker Compose, PromQL, YAML, Spring Boot Actuator Micrometer.

---

### Task 1: Prometheus 경보 규칙

**Files:**
- Create: `monitoring/prometheus/alerts.yml`
- Modify: `monitoring/prometheus/prometheus.yml`
- Test: `monitoring/prometheus/alerts.yml` with `promtool check rules`

**Step 1: Write the failing configuration check**

Run `promtool check rules monitoring/prometheus/alerts.yml` before the file exists.

Expected: the command fails because the rule file does not exist.

**Step 2: Write the minimal rules**

Add `ServiceDown` using `up == 0` for 2 minutes and `Http5xxRateHigh` using the standard `http_server_requests_seconds_count` metric, requiring non-zero request traffic. Include `severity`, `service`, and a short summary/description label set.

**Step 3: Connect the rule file**

Add `rule_files: ['/etc/prometheus/alerts.yml']` to `monitoring/prometheus/prometheus.yml`.

**Step 4: Run the configuration check**

Run `promtool check rules monitoring/prometheus/alerts.yml` and `promtool check config monitoring/prometheus/prometheus.yml`.

Expected: both commands pass.

**Step 5: Commit**

Run `git add monitoring/prometheus/alerts.yml monitoring/prometheus/prometheus.yml && git commit -m "feat: Prometheus 경보 규칙 추가"`.

### Task 2: Alertmanager Webhook 및 SMTP 라우팅

**Files:**
- Create: `monitoring/alertmanager/alertmanager.yml`
- Create: `monitoring/alertmanager/README.md`
- Modify: `.env.example`

**Step 1: Write the configuration validation**

Run `amtool check-config monitoring/alertmanager/alertmanager.yml` before the file exists.

Expected: the command fails because the configuration file does not exist.

**Step 2: Write the minimal receiver configuration**

Define one default route and two independent receivers. The Webhook receiver uses `${ALERTMANAGER_WEBHOOK_URL}`. The email receiver uses `${SMTP_SMARTHOST}`, `${SMTP_FROM}`, `${SMTP_AUTH_USERNAME}`, `${SMTP_AUTH_PASSWORD_FILE}`, and `${ALERT_EMAIL_TO}`. Use `smtp_auth_password_file` so the password is read from a mounted Secret file instead of being inserted into YAML. Enable `send_resolved`, grouping, repeat suppression, and environment substitution compatible with Alertmanager.

**Step 3: Document required variables**

Add unset-safe placeholder names to `.env.example`, including separate host and container paths for the SMTP password file, and document required SMTP/Webhook values in `monitoring/alertmanager/README.md`. Do not add real endpoint URLs, credentials, or recipient addresses.

**Step 4: Run configuration validation**

Run `amtool check-config monitoring/alertmanager/alertmanager.yml` with placeholder environment variables.

Expected: the command passes.

**Step 5: Commit**

Run `git add monitoring/alertmanager .env.example && git commit -m "feat: Alertmanager Webhook과 이메일 라우팅 추가"`.

### Task 3: Docker Compose 연결

**Files:**
- Modify: `docker-compose.yml`
- Modify: `monitoring/prometheus/prometheus.yml`

**Step 1: Write the Compose configuration check**

Run `docker compose config` with placeholder variables before adding the service wiring.

Expected: the current output does not include an Alertmanager service.

**Step 2: Add Alertmanager service**

Add an `alertmanager` service on port `9093`, mount `monitoring/alertmanager/alertmanager.yml`, the entrypoint, and the host SMTP password file at `/run/secrets/smtp-password`. Use the configuration file entrypoint. Mount `monitoring/prometheus/alerts.yml` into Prometheus and configure Prometheus `alerting.alertmanagers` to target `alertmanager:9093`.

**Step 3: Validate the rendered Compose file**

Run `docker compose config` with all documented placeholder variables.

Expected: the rendered configuration contains Prometheus, Alertmanager, the rule mount, and the Alertmanager dependency without unresolved required variables.

**Step 4: Commit**

Run `git add docker-compose.yml monitoring/prometheus/prometheus.yml && git commit -m "feat: Docker Compose에 Alertmanager 연결"`.
