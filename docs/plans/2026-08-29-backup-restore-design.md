# 백업과 복구 리허설 설계

## 목표

Docker Compose로 운영 중인 MySQL, MongoDB, Redis, Kafka의 상태를 백업하고, 백업 산출물을 이용한 복구 절차를 반복 실행할 수 있게 한다.

## 범위

- MySQL 전체 데이터베이스를 논리 백업한다.
- MongoDB `analytics` 데이터베이스를 archive 형식으로 백업한다.
- Redis RDB snapshot을 백업한다.
- Kafka 토픽 목록과 토픽 설정을 백업한다. Kafka 메시지 자체는 애플리케이션 DB와 DLQ 운영 정책의 대상이 아니므로 이번 범위에서 제외한다.
- 복구 스크립트는 기본 dry-run이며, 실제 쓰기는 `--confirm`을 명시해야 한다.

## 구성

- `scripts/backup/backup.sh`는 Compose 컨테이너 내부의 공식 CLI를 사용해 타임스탬프 디렉터리에 산출물을 만든다.
- `scripts/backup/restore.sh`는 백업 디렉터리를 검사하고 MySQL, MongoDB, Kafka 복구 명령을 실행한다.
- Redis는 복구 시 컨테이너의 `/data/dump.rdb`를 교체하므로 Redis 컨테이너 중지와 재기동이 필요하다.
- 비밀번호는 환경변수 또는 컨테이너 환경에서 읽고 파일에 기록하지 않는다.

## 운영 기준

- 목표 RPO는 24시간이다.
- 목표 RTO는 60분이다.
- 백업 디렉터리는 애플리케이션 호스트와 분리된 저장소로 복제해야 한다.
- 백업 완료만으로 복구 가능성을 보장하지 않으므로 월 1회 별도 임시 환경에서 복구 리허설을 수행한다.

## 검증

- 두 스크립트의 Bash 문법 검증.
- 백업 스크립트의 `--dry-run` 명령 출력 검증.
- 복구 스크립트의 기본 dry-run과 `--confirm` 누락 차단 검증.
- 실제 데이터 복구는 운영 자격 증명과 별도 복구 환경이 필요하므로 로컬 자동 검증에서 수행하지 않는다.
